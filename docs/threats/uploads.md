# Threats: uploads and refused content

Rows start `planned` and flip to `mitigated` when their test lands; same columns and status words as [threat-model.md](../threat-model.md). Owner stream: U (uploads). For the DROP rows the threat is the content a check refuses and the mitigation is the refusal.

## Uploads
| id | STRIDE | threat | L | I | mitigation | test | status |
|---|---|---|---|---|---|---|---|
| UP-01 | E | A presigned URL broader than one part | low | high | Each URL is one part, one key, PUT only, and short-lived | `UP-01 scope` | planned |
| UP-02 | D | Oversize upload or a part count beyond the bound | med | med | The declared size must equal the head size at complete; the part count is bounded | `UP-02 size` | planned |
| UP-03 | E | Using another user's upload id | med | high | Every upload route checks the owner | `UP-03 owner` | planned |
| UP-04 | D | Stale multipart uploads keep storage | med | low | A bucket lifecycle rule plus a cron abort | `UP-04 abort` | planned |
| UP-05 | T | Type confusion between the declared and the real kind | med | high | The stored type comes from the validated kind, never the name or the client | `UP-05 type` | planned |
| UP-06 | T | Cross-origin writes to the bucket | low | med | CORS allows only the bloop.here origin; checked live | `UP-06 cors` | planned |

## Refused content
| id | STRIDE | threat | L | I | mitigation | test | status |
|---|---|---|---|---|---|---|---|
| DROP-12 | E | Legacy Office files (.ppt, .doc, .xls) with a macro, an object pool or an encrypted storage | med | high | Refuse the file when its compound storage holds a macro, an ObjectPool or encryption, and when its kind's document stream (`WordDocument`, `Workbook` or `Book`, `PowerPoint Document`) is missing or is a storage, not a stream | `DROP-12 cfb` | mitigated |
| DROP-13 | E | A PDF that runs a script, starts a program, submits or imports data, plays rich media or jumps to another file, or carries an embedded file, an XFA form or encryption | med | high | A name-token scan of the file and of every object stream refuses the action types, not the keys that hold them: `/JS`, `/JavaScript`, `/Launch`, `/SubmitForm`, `/ImportData`, `/RichMedia`, `/GoToR` and `/GoToE` wherever they appear, inside `/OpenAction` and `/AA` included (a GoToR always names another file; a GoToE's target is another file or an embedded one), and the embedded and attached file keys `/EmbeddedFile`, `/EmbeddedFiles`, `/EF`, `/FileAttachment` and `/RF`, and `/XFA` (`macro_content`); `/Encrypt` is `encrypted`. An `/OpenAction` or `/AA` that holds only a GoTo or a destination passes (LaTeX hyperref and the PowerPoint, Word, Keynote, Google Slides and Acrobat exports write them), and so does any other action (a URI link, a named page action). A stream is an object stream when its dictionary names `/ObjStm` or holds both `/N` and `/First` (a reader takes an untyped one), and its keyword may end in CR LF, LF or a bare CR. An object stream not in the plain Flate form, over 8 MiB, past 4,096 per file or past 32 MiB inflated in all, an `/ObjStm` token or a direct `/First` count outside every object stream read, and a reference `/First` (an outline's, or a count a reader resolves) whose object reaches a stream word of any form (a keyword with white space before its EOL included) before its `endobj` without that stream's dictionary being read, is `bad_structure`. Every PDF is scanned in 8 MiB windows (one of at most 8 MiB is its one read), and the scan gives the same verdict however the file is cut. A scan's buffer stays within two windows and a 12 KiB overlap; with its text, the window in flight and an object stream's inflate, one scan measured 25 to 45 MiB of live buffers on a worst-case file (four 8 MiB incompressible object streams). No scan waits on another, so a few hostile near-cap PDFs validating at once in one isolate can pass its 128 MB: accepted, since the isolate is reset, no file is accepted and the hourly sweep deletes the stored objects; the reset also fails any unrelated request in flight in that isolate. Residual: this is a name scan, not a parser: stream payloads (content, XFA XML, embedded bytes) are not parsed, and a name in a string or comment refuses the file (fail closed), but an `endobj` in a string or a comment closes a reference `/First`'s object early, and a stream word in a string, an outline's title among them, refuses that object (fail closed); an auto-opening URI or other non-script action passes. Second layer, owned by the viewer (P2): pdf.js runs with scripting off, follows no action or link annotation by itself, and every link needs a tap with an explicit confirm | `DROP-13 pdf-active` (unit: a producer corpus passes, each dangerous action refused, the untyped object stream, reference `/First` and file attachment proofs of concept refused, the chunked and whole scans agree over the corpus and random mutations) | mitigated |
| DROP-14 | E, I | An Office file with an external relationship, or a macro-enabled type | med | high | Refuse any relationship with an external target and the docm, xlsm and pptm content types | `DROP-14 external` | mitigated |
| DROP-15 | T | Bad magic bytes or brand (webp, gif, heic, webm), or text that is not UTF-8 or is oversize | med | med | Refuse a file whose magic or brand does not match its kind, and text that is not UTF-8 or is over its size cap; text that is another format (a binary magic, `%PDF`, or an HTML, `<script`, `<svg` or `<?xml` start in its head, or a zip local header or end record anywhere) is `bad_structure` | `DROP-15 magic` `DROP-02 polyglot` | mitigated |
| DROP-16 | D | An image with a huge pixel size (a decompression bomb) that takes down the room screen's tab | low | med | The size in the image's own header (PNG, JPEG, GIF, WebP; a GIF's logical screen and every frame, each frame with its offset inside the screen) is at most 100 megapixels; a JPEG's frame header and a GIF's frames are walked through the read plan (a JPEG at most 4 reads of 256 KiB, a GIF to its trailer in 8 MiB windows, as many as the read plan has left, at most 1,000,000 blocks and a sub-block per 255 bytes the plan could read); a missing or zero size, an unknown GIF block or a walk past a cap is `bad_structure`, one over the pixel cap is `too_large`; HEIC dimensions are the converter's limits. Residual: a JPEG whose frame header lies past the first 1 MiB is refused (`bad_structure`) | `DROP-16 pixels` | mitigated |
